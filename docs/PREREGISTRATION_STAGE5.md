- 이 문서는 [PREREGISTRATION.md](PREREGISTRATION.md)(0~4단계)에 이어지는 추가 등록이다. 앞 문서의 내용과 판정(A1~A9, B1~B2, C1~C2, D1~D2)은 **바꾸지 않는다.** A8(개별 질량)과 A9(f(t) chirp mass)는 '재현 안 됨'으로 남는다. 여기서 정하는 E, F 항목은 새 방법에 대한 새 판정이고, A8·A9를 대신하지 않는다.

## 0. 이 문서를 커밋한 시점의 상태

**아직 하지 않은 것**

- GW151226 strain, O1의 다른 구간 strain, GWTC-1 사후분포 표본 파일을 하나도 받지 않았다.
- 아래 2~6절의 방법을 실제 자료(GW150914 자료 포함)에 돌리지 않았다.

**이미 한 것 (결과에 영향을 줄 수 있어 모두 적는다)**

1. 문헌 PDF를 읽었다(1절).
2. GWOSC API의 JSON 메타데이터를 읽었다: GW151226 event JSON(파일 이름, 카탈로그 값), O1 strain 파일 목록과 파일별 `dutycycle_percent`, `nans_fraction`(`scripts/select_background_files.py`, 결과는 `data/meta/background_files.json`). strain 값은 읽지 않았다.
3. bilby 2.8.2를 설치하고(가상환경 323 MB → 379 MB) **모의 잡음**에서 가능도 계산 시간을 쟀다(8초, 2048 Hz, IMRPhenomD, 거리·위상·시각 주변화: 1회 1.9~3.1 ms).
4. 저질량 뱅크를 만들었다(4절, `results/bank_lowmass.csv`, 1,318개). 뱅크 배치에 쓴 PSD는 **이미 가진 GW150914 파일**의 H1 처음 512초다. 새 자료는 쓰지 않았다.
5. 탐색 코드를 일반화했다(구간 길이, 정렬 spin, 출력 표본 간격). 0~4단계 테스트 24개는 그대로 통과한다.
6. 2절의 f(t) 방법을 **해석적 PSD로 만든 Gaussian 모의 잡음**(`tests/conftest.py`의 `model_psd`)에서 개발했다. 시도한 세 가지와 모의 시험 수치:
   - Q-transform 능선을 동적 계획법으로 따라간 뒤 직선 fit: SNR 20에서 25개 중 3~11개 측정 실패, 산포 13~35 %. 버림.
   - Q-transform 위에 Newton 궤적을 얹어 에너지 합을 최대화: 산포 17~59 %, 질량이 클수록 크게 치우침. 버림.
   - Newton 차수 chirp 하나짜리 결맞음 필터(2절): 대역 30~150 Hz에서 SNR 20일 때 (추정값/참값)의 중앙값 1.13~1.25, 산포(16~84 % 반폭) 3~8 %. SNR 13일 때 중앙값 1.11~1.24, 산포 7~14 %. 가장자리 해 0~1개(30개 중). 대역 30~60, 30~80, 30~100 Hz는 산포가 더 커서(12~150 %) 30~150 Hz로 정했다. **이 방법을 채택한다.**
7. 0~4단계에서 이미 본 것: GW150914의 모든 결과. 특히 Q-transform ridge fit의 참고 값(H1 35.9, L1 39.6 M☉)과 PE 결과(ℳ 31.30, q 0.86)를 알고 있다.

**사전 지식 고지.** 분석을 수행하는 AI 에이전트는 GW151226의 알려진 결과(SNR 약 13, chirp mass 약 9.7 M☉, 양의 유효 spin)를 사전 지식으로 안다. 4절의 뱅크 범위(ℳ 7~13 M☉)는 이 지식을 써서 좁게 잡았다. 따라서 GW151226 탐색은 "시각을 모르는 탐색"이지 "질량을 모르는 탐색"이 아니다.

## 2. 항목 1 — f(t) chirp mass를 견고한 방법으로 (판정 E)

**방법 (Newton chirp 필터).** 최저 차수 chirp 법칙 df/dt = (96/5) π^{8/3} (Gℳ/c³)^{5/3} f^{11/3} 하나만 쓴다. 이 법칙을 따르는 신호의 주파수 영역 모양은 h̃(f) ∝ f^{−7/6} exp[−i (3/128)(πGℳf/c³)^{−5/3}]이다. 매개변수가 ℳ 하나뿐인 이 chirp들을 30~150 Hz(앞 문서 4절의 f(t) 절차와 같은 대역)로 잘라 자료와 상관시키고, SNR이 가장 큰 ℳ을 추정값(ℳ_raw)으로 삼는다. post-Newtonian 항, merger, ringdown, 질량비, spin은 모형에 없다. f(t) 점을 하나씩 읽어 직선을 긋는 대신 같은 직선 관계를 자료 전체에 한 번에 맞추는 것이며, IMRPhenomD 뱅크와는 독립이다.

- ℳ 격자: GW150914는 8~80 M☉, GW151226은 5~20 M☉, 로그 간격 0.25 %. 격자 정점에서 ln ℳ에 대한 포물선 보간.
- 시각: matched filter 정점 시각(주입은 주입 시각) ±0.15초 안에서 최대. PSD, 구간 길이(32초), 창은 앞 문서 4절과 같다.
- 최댓값이 격자 가장자리면 '측정 실패'.
- 그림: Q-transform 위에 추정한 Newton 궤적 f(t; ℳ_raw, t_c)를 겹쳐 그린다(눈으로 보는 확인용, 판정 없음).

**주입으로 검증·보정.** 방법은 치우친다(모의 잡음에서 약 +20 %, 0절). 실제 잡음에서 다음과 같이 잰다.

- 잡음: 사건에서 32초 이상 떨어진 구간(사건 파일 안)에서 무작위. H1, L1 따로.
- 신호: IMRPhenomD. GW150914용: ℳ_true ∈ {20, 25, 30, 35, 40} M☉, q ∼ U(0.5, 1), spin 0. GW151226용: ℳ_true ∈ {8, 9, 10, 11, 12} M☉, q ∼ U(0.25, 1), χ1 = χ2 ∼ U(−0.1, 0.5).
- 세기: 그 검출기에서 그 사건을 잰 matched-filter SNR과 같은 최적 SNR. GW150914는 `results/event.json`의 H1 19.69, L1 13.52. GW151226은 5단계 탐색에서 잰 값.
- 개수: (ℳ_true, 검출기)마다 100개. seed 20261116.
- 보정 곡선: 검출기마다 ℳ_true에 대한 ℳ_raw 중앙값을 선형 보간한 뒤 뒤집어 ℳ_cal = g⁻¹(ℳ_raw). 격자 밖은 양끝 구간의 기울기로 외삽한다.
- 산포 s: 보정한 주입 추정값의 16~84 % 반폭(상대값). 사건 결과에 가장 가까운 ℳ_true 격자점의 값을 쓴다.
- 두 검출기 결합: 1/s² 가중 평균, σ = (Σ 1/s²)^{−1/2}.

**검증 기준 (GW150914용 주입, V).**

- V1: 두 검출기 모두 ℳ_raw 중앙값이 ℳ_true에 대해 단조 증가(보정 곡선을 뒤집을 수 있다).
- V2: H1에서 ℳ_true = 30의 산포 s ≤ 15 %.
- V3: 측정 실패(가장자리 해) 비율이 전체 주입의 5 % 이하.
- 셋 중 하나라도 어기면 "방법 검증 실패"로 보고하고, 사건에 적용한 값은 참고로만 적는다.

**사건 판정 (GW150914).**

| 번호 | 항목 | 기준 | 이유 |
|---|---|---|---|
| E1 | ℳ_raw (H1), 보정 전 | 22.8 ~ 38.0 M☉ | A9와 같은 범위(30.4 ± 25 %)를 그대로 쓴다. 모의 잡음 시험대로 +20 % 치우치면 약 36~38이 나와 **상한에 걸칠 것으로 예상한다.** [BP]가 같은 종류의 Newton fit으로 ∼37 M☉을 얻은 것과 같은 치우침이다 |
| E2 | ℳ_cal (H1·L1 결합), 주입 보정 후 | 90 % 구간 [ℳ_cal(1 − 1.645σ), ℳ_cal(1 + 1.645σ)]이 문헌 90 % 구간 28.5 ~ 32.5 M☉과 겹침 | 보정이 맞다면 치우침이 없어야 한다. 구간이 넓으면 쉽게 통과하므로 σ를 함께 보고한다 |

**GW151226.** 같은 절차를 적용하고 ℳ_raw, ℳ_cal, σ를 보고한다. 긴 inspiral(수십 사이클)에서 Newton 위상은 실제 위상과 많이 어긋나므로 SNR 회수가 낮고 보정 곡선이 불안정할 수 있다. 판정 범위는 두지 않고, V1~V3와 같은 검증 수치를 GW151226용 주입에 대해 보고한다.

## 3. 항목 2 — 질량비와 개별 질량: 정렬 spin을 넣은 PE (판정 F)

THEORY.md에 "matched filter 뱅크의 최대 SNR 격자점이 질량비를 잘 제약하지 못하는 이유"를 정리한다(위상의 최저 차수는 ℳ만, η는 1PN, spin은 1.5PN에서 η와 얽힘. 사이클 수가 적은 고질량 계에서는 M–η 축퇴).

**주 분석: bilby 2.8.2 + dynesty.** 설치가 되므로 표준 도구를 쓴다.

- 자료: matched filter H1 정점 시각 t_trig 기준 [t_trig − 6, t_trig + 2]의 8초, H1·L1. 4096 → 2048 Hz(`scipy.signal.resample_poly`). 대역 20~896 Hz. Tukey 창 roll-off 0.4초.
- PSD: 앞 문서 4절의 방식(사건 중심 512초, 4초 조각 중앙값 Welch)으로 추정해 bilby에 넘긴다. 보정(calibration) 불확도는 넣지 않는다.
- 파형: IMRPhenomD(정렬 spin, (2,2) 모드, 세차 없음), 기준 주파수 20 Hz.
- 매개변수 11개: ℳ, q, χ1, χ2, d_L, θ_JN, ψ, φ, α, δ, t_c. 거리·위상·시각은 가능도에서 주변화하고 나중에 복원한다.
- 사전분포: m1, m2에 균등(`UniformInComponentsChirpMass`, `UniformInComponentsMassRatio`). 검출기 기준 ℳ 범위는 GW150914 25~40, GW151226 9.0~10.5 M☉. q 0.125~1. χ1, χ2는 크기 0~0.99 균등·방향 등방인 spin의 정렬 성분(`AlignedSpin`). d_L ∝ d², 50~2000 Mpc. 방향 등방, cos θ_JN 균등, ψ 균등, t_c는 t_trig ± 0.1초.
- sampler: dynesty, nlive 500, `acceptance-walk`, naccept 30, dlogz 0.1, seed 20261116. 체크포인트를 남긴다.
- 사건 하나에 6시간이 넘으면 중단하고 그 사실을 보고한다. 이 경우 아래 보조 분석으로 판정한다.
- 원천 기준 환산: 표본마다 d_L → z (평탄 ΛCDM, H0 = 67.9 km/s/Mpc, Ω_m = 0.3065, [C]와 같은 Planck 2015), m_src = m_det / (1 + z). 직접 적분한다.

**보조 분석: 직접 쓴 가능도 + emcee.** 앞 문서 9절의 profile likelihood에 spin 하나를 더한다: (ℳ, q, χ), χ1 = χ2 = χ, χ ∼ U(−0.9, 0.9). walker 32개, 3000 step, 앞 1000 step 버림. bilby 결과와 나란히 보고한다(판정 없음. bilby가 실패한 경우에만 판정에 쓴다).

**문헌 사후분포와의 비교.** GWTC-1 공개 표본(Overall)에서 검출기 기준 m1, m2, ℳ, q, χ_eff를 계산한다(χ_eff = (m1 a1 cos θ1 + m2 a2 cos θ2) / (m1 + m2)).

**판정 (GW150914).**

| 번호 | 항목 | 기준 |
|---|---|---|
| F1 | 개별 질량, 검출기 기준 (A8과 같은 범위) | m1 중앙값이 34.6 ~ 44.5 **그리고** m2 중앙값이 26.9 ~ 35.8 M☉ |
| F2 | 질량비 | q의 90 % 구간이 문헌 구간 0.62 ~ 0.99([PE])와 겹침. q = 1이 90 % 구간 안에 있는지도 적는다 |
| F3 | 유효 spin | χ_eff의 90 % 구간이 문헌 구간 −0.24 ~ +0.09([PE])와 겹침 |
| F4 | GWTC-1 표본과의 겹침 | ℳ, q, χ_eff, m1, m2(검출기 기준) 다섯 양 각각에서 "우리 중앙값이 GWTC-1 90 % 구간 안 **그리고** GWTC-1 중앙값이 우리 90 % 구간 안". 다섯 모두 만족하면 '겹침'. 만족한 개수를 보고한다 |

- 미리 적는 한계: 세차와 고차 모드가 없고 보정 불확도·PSD 불확도를 넣지 않으므로 구간이 문헌보다 좁을 수 있다. 문헌 값은 두 파형 모형의 평균이다. A8의 판정은 F1의 결과와 무관하게 '재현 안 됨'으로 남는다.

## 4. 항목 3 — 두 번째 사건 GW151226 (판정 G)

## 5. 항목 4 — 배경 확장 (판정 H)

**자료 선택 (메타데이터만으로, strain을 보기 전에 확정).** O1 4 kHz 일괄(bulk) 파일(4096초, `LOSC_4_V1`) 가운데 H1과 L1이 **모두** `dutycycle_percent = 100`, `nans_fraction = 0`이고 사건 파일과 겹치지 않는 것을, 사건 시각에서 가까운 순서로 고른다. GW150914용 8개, GW151226용 4개. `scripts/select_background_files.py`가 고른 GPS 시작 시각:

- GW150914: 1126309888, 1126313984, 1126318080, 1126322176, 1126404096, 1126105088, 1126100992, 1126092800 (사건에서 0.6 ~ 1.9일)
- GW151226: 1135140864, 1135144960, 1135153152, 1135157248 (사건 뒤 1.8 ~ 6.4시간)
- 개수는 계산 시간으로 정했다(GW150914 뱅크 496개는 파일 쌍당 약 10분, 저질량 뱅크 1,318개는 약 12분으로 예상).
- 일괄 파일과 사건 파일의 보정 판(calibration version)이 같은지는 문서로 확인하지 못했다. 사건 파일과 겹치는 일괄 파일(GW150914: 1126256640)을 받아 겹치는 구간의 값이 같은지 비교해 보고한다(이 파일은 배경에 쓰지 않는다).

**절차.** 각 파일에서 사건 파일과 **같은 뱅크, 같은 절차**로 단일 검출기 trigger를 만든다(GW150914: 앞 문서 6절 그대로, 거친 뱅크 496개. GW151226: 4절). 파일들의 유효 구간을 시간 순서로 이어 붙여 하나의 고리(ring)로 보고, L1 trigger를 0.1초의 정수배만큼 고리 위에서 옮긴다.

- GW150914: 9개 파일 × 4080초 = 36,720초, 이동 367,199번, T_bg = 36,720² / 0.1초 ≈ 427년.
- GW151226: 5개 파일 × 4064초 = 20,320초, 이동 203,199번, T_bg ≈ 131년.
- 주 추정에서는 사건 ±1초의 trigger를 뺀다. 빼지 않은 결과도 보고한다.
- **H1** (GW150914), **H2** (GW151226): 사건의 ρ̂c 이상인 배경 후보가 0개인가. 0개면 FAR < 1/T_bg와 포아송 90 % 상한 2.3/T_bg를 보고한다.
- 추가 파일의 zero-lag 동시 발생 후보도 보고한다(가장 큰 ρ̂c와 시각).

**trigger 재사용 문제를 줄이고 드러내는 방법.**

1. 이동 간격(0.1초)이 동시 발생 창의 두 배(0.03초)보다 커서 한 (H1, L1) trigger 쌍은 많아야 한 번의 이동에서만 동시 발생한다. 자료가 길어지면 서로 다른 쌍의 수가 T²에 비례해 늘어난다. 쌍의 수를 보고한다.
2. **모든 쌍 추정(all-pairs).** 이동 격자를 쓰지 않고 모든 (H1, L1) 쌍을 한 번씩 센다. 통계량이 x 이상인 쌍이 n(x)개면 우연 동시 발생률은 R(x) = n(x) · 2w / T² (w = 15 ms). time slide 추정과 기댓값이 같고 쌍을 약 3.3배 더 쓰므로 분산이 작다. n = 0이면 R < 2w/T²를 함께 보고한다. 주 판정(H1, H2)은 time slide로 하고 이것은 교차 확인이다.
3. **파일 단위 jackknife.** 파일 하나의 trigger를 두 검출기에서 모두 빼고 다시 추정하기를 파일 수만큼 반복해, ρ̂c ≥ 8, 8.5, 9에서의 배경률 표준오차를 구한다.
4. **재사용 없는 분포.** 배경 후보를 ρ̂c가 큰 순서로 훑으며, H1 trigger와 L1 trigger가 둘 다 아직 쓰이지 않은 후보만 남긴다(각 trigger를 많아야 한 번 사용). 이 분포는 배경률을 낮게 치우쳐 추정하므로 FAR 계산에는 쓰지 않고, 원래 분포의 꼬리가 소수의 큰 trigger에 얼마나 기대는지를 보이는 데만 쓴다. 가장 큰 배경 후보 10개에 들어 있는 서로 다른 H1·L1 trigger 수도 보고한다.
- 한계(미리 적음): (a) 여전히 수 시간 분량의 잡음이다. 문헌의 한계(203,000년에 1번, < 6 × 10⁻⁷ /yr)는 재현 대상이 아니다. (b) 며칠 떨어진 구간은 잡음 상태가 사건 시각과 다를 수 있다. (c) 뱅크가 좁고, 같은 템플릿을 요구하지 않으며, data-quality veto를 쓰지 않는다(앞 문서와 같음). (d) time slide는 두 검출기의 잡음이 독립이라는 가정에 기댄다.

## 6. 항목 5 (선택) — 작은 CNN 탐지기와 비교 (판정 없음, 결과 그대로 보고)

시간이 남을 때만 한다. 하게 되면 아래 절차를 따른다. 하지 않으면 하지 않았다고 적는다.

- 입력: 한 검출기의 whitening한 자료(구간 PSD, 20~500 Hz 대역 통과)를 2048 Hz로 낮춘 1초 창. 출력: 신호가 들어 있을 logit.
- 구조: 1차원 합성곱 4층 + 전역 평균 + 선형층, 매개변수 10만 개 이하. PyTorch(CPU).
- 학습 자료: 잡음은 5절의 GW150914용 추가 파일 8개(H1·L1). 신호는 앞 문서 7절과 같은 모집단(IMRPhenomD, 검출기 기준 (38.9, 31.6) M☉, 방향·자세 무작위)을 최적 단일 검출기 SNR 4~20 균등으로 넣고, merger를 창의 0.6~0.9초에 둔다. 신호 2만 + 잡음 2만 창, 검증용 10 % 분리, seed 고정.
- 평가 자료: 사건 파일(학습에 쓰지 않음). 사건 ±1초는 뺀다.
- 탐지 절차: 1/16초 간격으로 창을 옮기며 logit을 계산, ±0.5초 안 최대를 trigger로, 두 검출기 trigger가 0.08초 안이면 동시 발생, 순위 통계량은 logit의 합. 배경은 0.2초 간격 time slide.
- 비교: 3단계의 주입 900개(같은 매개변수, `results/injections.npz`)를 다시 만들어 넣고, **두 방법 모두 사건 파일 배경에서 FAR = 1/yr이 되는 문턱**에서 거리별 탐지 효율을 비교한다. matched filter 쪽은 3단계 결과(`results/injections.csv`, `results/background.json`)에서 같은 FAR의 문턱으로 다시 계산한다.
- CNN이 더 낫지 않으면 그대로 보고한다. 미리 적는 예상: 신호 모양을 정확히 아는 경우 matched filter가 Gaussian 잡음에서 최적이므로 CNN이 같거나 낮을 것이다.

### 기록 A (2026-11-16) — GW151226 사건 파일의 H1 자료는 앞 1,925초가 비어 있다

- 받은 파일 `H-H1_GWOSC_4KHZ_R1-1135134303-4096.hdf5`는 파일 시각 0~1925초가 NaN이고 DATA 비트가 꺼져 있다(H1이 관측 상태가 아니었다). 사건(2047.6초)은 H1 자료가 시작되고 약 123초 뒤다. 0절의 메타데이터 확인은 일괄 파일만 대상으로 했고 사건 파일의 가동률은 미리 보지 않았다.
- 미리 정한 규칙(NaN이 있는 구간은 버림)대로 처리한다. 사건 파일의 동시 관측 유효 시간은 4,064초가 아니라 2,112초(구간 61~126)다. 따라서 5절의 GW151226 고리 길이는 20,320초가 아니라 18,368초, T_bg는 약 131년이 아니라 약 107년이 된다.
- 구현 추가: PSD를 추정하는 512초 창을 NaN이 없는 연속 구간 안으로 밀어 넣는다(`psd.psd_for_segment`의 `bounds`). 사건 구간의 H1 PSD는 사건 중심 ±256초가 아니라 파일 시각 1925~2437초에서 추정된다. 연속 구간이 128초보다 짧으면 그 구간은 버린다. NaN이 없는 파일에서는 이전과 같은 결과다.

### 기록 B (2026-11-16) — 보조 PE의 사전분포 범위

- 3절은 보조 분석(emcee)의 ℳ, q 범위를 따로 적지 않았다. GW150914는 앞 문서 9절과 같은 20 ≤ ℳ ≤ 45, 0.2 ≤ q ≤ 1을, GW151226은 bilby와 같은 9.0 ≤ ℳ ≤ 10.5, 0.125 ≤ q ≤ 1을 쓴다. GW151226은 템플릿이 길어 16초 구간([t − 12, t + 4])을 쓴다. 결과를 보기 전에 정했다.

### 기록 C (2026-11-16) — bilby와 dynesty 버전

- `uv pip install bilby`가 함께 깐 dynesty 3.2.0에서는 bilby 2.8.2의 sampler가 시작하자마자 `ImportError: cannot import name 'apply_reflect' from 'dynesty.utils'`로 멈췄다(두 사건 모두 9초 만에 종료, 표본 없음). dynesty를 2.1.5로 내려 다시 돌렸다. 설정(nlive 500, acceptance-walk, naccept 30, dlogz 0.1, seed)은 3절 그대로다. 0절에서 쟀던 것은 가능도 계산 시간뿐이라 이 문제를 미리 보지 못했다.
- bilby는 시각을 주변화할 때 `geocent_time`을 구간 시작 시각에 고정하고 그 뒤 0.1초 폭의 사전분포 범위를 적분한다. 본 실행 전에 `--dry` 점검(탐색 최적 질량에서 방향을 3,000번 무작위로 뽑은 최대 로그 가능도비: GW150914 264.6, GW151226 68.1, ρ_net²/2는 각각 285.3, 81.1)으로 신호가 가능도에 들어오는 것을 확인했다. 이 점검은 질량을 탐색 결과에 고정한 것이고 사후분포를 보지 않았다.

### 기록 D (2026-11-16) — 2절에서 미리 적은 예상 가운데 틀린 것

- GW151226에 대해 "Newton 위상이 많이 어긋나 SNR 회수가 낮고 보정 곡선이 불안정할 수 있다"고 적었다. 실제로는 Newton chirp 필터가 전체 템플릿 SNR의 83 %(H1), 73 %(L1)를 회수했고 보정 곡선은 단조였으며 치우침은 +1~6 %였다. 30~150 Hz 대역 안에서는 chirp mass와 도착 시각을 조금 옮기는 것으로 고차 항의 대부분이 흡수된다는 뜻이다.

### 변경 2 (2026-11-16, CNN 결과를 본 뒤) — CNN의 동시 발생 창

- **원래 절차의 결과를 먼저 적는다.** 6절 그대로(동시 발생 창 0.08초, time slide 0.2초, FAR 1/yr): CNN은 주입 900개 중 31개, matched filter는 272개를 탐지했다. 민감 거리는 CNN 421 Mpc, matched filter 1,102 Mpc. 250 Mpc에서 효율은 0.14 대 0.90. CNN만 찾은 주입은 0개다. **CNN이 훨씬 낮다**(`results/cnn_eval.json`). 이 결과가 6절의 비교 결과다.
- 원래 절차에서는 GW150914 자체도 CNN의 동시 발생 후보로 잡히지 않았다. 단일 검출기 logit은 크지만 두 검출기의 trigger 시각이 0.08초 안에 들지 않았다.
- 원인(절차 설계의 실수): 학습 때 merger를 창의 0.6~0.9초 어디에나 두었기 때문에, 신호가 있으면 연속한 창 대여섯 개(0.3초)가 모두 높은 logit을 내고 그중 최대인 창은 잡음이 정한다. 그래서 CNN trigger의 시각은 ±0.15초쯤 흔들리는데 동시 발생 창을 0.08초로 잡았다. 자료와 무관하게 예상할 수 있었다.
- 바꾼 절차(참고 결과, `results/cnn_eval_wide.json`): 동시 발생 창 0.35초, time slide 0.75초, 주입 시각 허용 ±0.5초. 이동 간격이 커져 CNN 배경 시간이 1년에 못 미치므로, FAR은 1/yr 대신 **1/(CNN 배경 시간)**으로 두 방법을 맞춘다. 결과는 README에 원래 절차의 결과와 나란히 적는다.
- 참고 결과의 수치: FAR 1.42/yr(CNN 배경 시간 0.70년)에서 CNN은 900개 중 111개, matched filter는 272개를 탐지했다. 민감 거리는 CNN 617 Mpc, matched filter 1,102 Mpc. 250 Mpc에서 효율은 0.57 대 0.90. CNN만 찾은 주입은 1개다. 창을 넓혀도 **CNN이 더 낮다.**
- GW150914 자체는 넓힌 창에서도 CNN의 동시 발생 후보가 아니다. 단일 검출기 logit은 두 검출기 모두 파일 전체에서 가장 크지만(H1 46.3, L1 29.3) 최대인 창의 시각이 0.44초 떨어져 있다(파일 시각 2048.0과 2047.5625초. `data/cache/cnn_scores_<det>.npz`에서 직접 확인, git 제외).
